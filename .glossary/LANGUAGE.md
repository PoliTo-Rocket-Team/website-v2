# PoliTo Rocket Team website architecture vocabulary (LANGUAGE)

The repo-owned architecture vocabulary. One row per term: the canonical definition, and where a name
has drifted, what the term is **not**. When the code and this file disagree, the code is
authoritative and this file is the doc to fix.

## Code layout

| Term | Definition | Not |
|---|---|---|
| code-built rocket | A rocket drawn in Three.js from code, with numbers measured off a reference model: Cavour in [components/landing/rocket-cavour.tsx](../components/landing/rocket-cavour.tsx). `design/cavour.glb` is the measurement reference only and is not served ([design/HANDOFF.md](../design/HANDOFF.md)). | A served 3D mesh. |
| landing component | A component of the redesigned public site, in `components/landing/`, each tied to one approved board ([design/HANDOFF.md](../design/HANDOFF.md)). | A component in the `components/` root, which serves the legacy pages and dashboard. |
| legacy route group | `app/(legacy)/`: the pages from before the redesign (apply, sign-in, dashboard, demos), kept under their own layout. A replacement deletes the old route in the same change ([0001](../.decisions/0001-reuse-website-v2-nothing-protected.md)). | |
| server action | A function in a `"use server"` file that the client can call: [app/actions/get-applications.ts](../app/actions/get-applications.ts), [app/actions/get-user-scope.ts](../app/actions/get-user-scope.ts) and the dashboard positions `server-actions.ts`. | A `server-only` module. Most files in `app/actions/` import `server-only` without `"use server"`, so the client cannot call them. |
| UI primitive | A shadcn/ui component on Radix in `components/ui/`, the base other components build on ([design-system-manifest.md](../design-system-manifest.md)). | |

## Data and caching

| Term | Definition | Not |
|---|---|---|
| audit query | A query run through `runAuditQuery`, which first sets `request.jwt.claim.sub` to the current user id in the same batch, so the audit log trigger can record who changed the row ([lib/db-audit.ts](../lib/db-audit.ts)). | |
| better_auth schema | The Postgres schema that holds Better Auth's own tables (user, session, account, verification), apart from the app's `public` schema ([db/schema/better-auth.ts](../db/schema/better-auth.ts)). | |
| cache tag | A name given with `cacheTag` inside a `"use cache"` function, and expired with `updateTag` after a write. Tags in use: `apply-positions`, `public-apply-positions`, `org-structure` ([app/actions/get-apply-positions.ts](../app/actions/get-apply-positions.ts), [app/actions/get-member-scopes.ts](../app/actions/get-member-scopes.ts)). | `unstable_cache` and `revalidateTag`, the older API named in [0003](../.decisions/0003-neon-direct-pooled.md); the code does not use them. |
| migration | A SQL file in `drizzle/`, generated by `pnpm db:generate` from `db/schema/`, kept as generated and treated as append-only ([AGENTS.md](../AGENTS.md), [README.md](../README.md)). | |
| pooled endpoint | Neon's connection-pooling host, the one `DATABASE_URL` points at for the app; the direct host is for migrations only ([0003](../.decisions/0003-neon-direct-pooled.md)). | |
| snapshot | A whole small table read once and cached, then filtered in memory per caller, as with `DivisionStructureSnapshotRow` and `PositionSnapshotRow` ([app/actions/get-member-scopes.ts](../app/actions/get-member-scopes.ts), [app/actions/get-apply-positions.ts](../app/actions/get-apply-positions.ts)). | |

## Hosting

| Term | Definition | Not |
|---|---|---|
| host-agnostic | The rule that `app/`, `lib/` and `db/` use no host-specific API, so leaving Vercel is a config change; the app must run as plain `next build && next start` ([0002](../.decisions/0002-vercel-hobby-host-agnostic.md)). | |
